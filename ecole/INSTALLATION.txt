 A. ESSAI EN 2 MINUTES, SUR VOTRE ORDINATEUR (gratuit)
===============================================================================

    unzip terminish-ecole-deploiement.zip
    cd terminish-ecole
    bash deploy/gratuit/installer-linux.sh --demo

  → installe les dépendances, cloudflared (sans sudo), affiche un lien HTTPS public.

  COMPTES DE DÉMONSTRATION (mode --demo) :
      admin@terminish.tg    admin1234    console éditeur (écoles, paiements)
      directeur@demo.tg     demo1234     chef d'établissement
      prof.maths@demo.tg    prof1234     enseignant
      eleve@demo.tg         eleve1234    élève / parent

  ⚠ Le mot de passe généré affiché par le lanceur ne concerne QUE le mode normal
    (npm run partage) sur une base neuve. En mode --demo, c'est admin1234.

 B. MISE EN LIGNE PERMANENTE AVEC DOCKER (VPS)
===============================================================================

    cp .env.example .env
    nano .env       # DOMAIN=ecole.votre-domaine.tg, ADMIN_EMAIL, ADMIN_PASSWORD,

  Vérification : https://votre-domaine/api/health → {"ok":true,...}

 C. MISE EN LIGNE SANS DOCKER (VPS + systemd + Nginx)
===============================================================================

    npm ci --omit=dev
    cp .env.example .env && nano .env
    cp deploy/terminish-ecole.service /etc/systemd/system/

 « CE SITE EST INACCESSIBLE » / ERR_NAME_NOT_RESOLVED
===============================================================================

  Un tunnel rapide Cloudflare (lien xxxx.trycloudflare.com) n'existe que tant
  que la commande tourne. À l'arrêt (Ctrl+C, veille, fermeture du terminal),
  l'adresse est supprimée définitivement : elle ne reviendra pas.

      npm run lien       → le site est-il en ligne ? quel est le lien actuel ?
      npm run partage    → repartir (un NOUVEAU lien est créé)

  Le lanceur relance automatiquement le tunnel s'il tombe (5 tentatives).
  Pour une adresse qui ne change jamais : Tailscale (section suivante).

 FIREBASE : UNE ADRESSE DÉFINITIVE (https://mon-ecole.web.app)
===============================================================================

  Firebase Hosting publie l'INTERFACE (HTML/CSS/JS) gratuitement, sans carte
  bancaire, sur une adresse qui ne change jamais. Le SERVEUR (Node + base)
  reste sur votre Chromebook : Firebase ne peut pas l'exécuter sans carte.

  Le script fait tout d'un coup : il lit l'adresse fixe du tunnel Tailscale,
  l'écrit dans public/config.js, associe le projet Firebase, publie, et
  enregistre les réglages CORS + cookie dans le fichier .env.

      1)  bash deploy/gratuit/lien-stable.sh --tailscale
      2)  npx firebase-tools login
      3)  bash deploy/gratuit/firebase.sh --projet NOM-DU-PROJET
      4)  bash deploy/gratuit/tout.sh

  Le projet se crée (une seule fois) sur https://console.firebase.google.com
  → « Ajouter un projet » → forfait Spark (gratuit). Le nom choisi devient
  l'adresse : https://NOM.web.app

  Autres options :
      bash deploy/gratuit/firebase.sh --etat       # où en est-on ?
      bash deploy/gratuit/firebase.sh --preparer   # écrire sans publier
      bash deploy/gratuit/firebase.sh --annuler    # revenir au site local

  Détail complet : FIREBASE.md

 UN LIEN QUI NE CHANGE JAMAIS — GRATUIT, SANS CARTE BANCAIRE (Tailscale)
===============================================================================

  ⚠ Depuis le 23/10/2026, npm run partage RÉUTILISE l'adresse fixe si elle
    existe : il affiche « Lien PERMANENT : https://....ts.net » et n'ouvre
    aucun lien jetable. S'il n'y en a pas, il rappelle la commande à lancer.

  Un lien xxxx.trycloudflare.com est éphémère : il meurt avec la commande.
  Pour une adresse stable SANS carte bancaire, utilisez Tailscale Funnel :
  vous obtenez https://<machine>.<reseau>.ts.net, gratuit à vie, HTTPS inclus,
  sans ouvrir aucun port dans la box (fonctionne en CGNAT et sur Chromebook).

      # terminal 1
      npm run partage

      # terminal 2  (Ctrl+Shift+T)
      bash deploy/gratuit/lien-stable.sh --tailscale

  Le script installe Tailscale, vous fait vous connecter (Google ou GitHub,
  aucune carte), puis affiche les 2 options à activer dans la console :
      https://login.tailscale.com/admin/dns  → MagicDNS + Enable HTTPS
  et la commande finale :

      sudo tailscale funnel --bg 3000
      # → Available on the internet: https://mon-pc.requin-bleu.ts.net

  Autres commandes du script :
      bash deploy/gratuit/lien-stable.sh --etat      # où en est-on ?
      bash deploy/gratuit/lien-stable.sh --ip        # diagnostic IP/CGNAT
      bash deploy/gratuit/lien-stable.sh --duckdns NOM TOKEN   # nom DuckDNS

  ⚠ Une fois le tunnel ouvert, le site est public : changez le mot de passe
    administrateur (npm run motdepasse) et n'utilisez pas partage:demo.

  ── Si un jour vous avez une carte bancaire (annexe) ──────────────────────
  Une VM Oracle Cloud « Always Free » fait tourner le site 24 h/24, même
  Chromebook éteint. Carte demandée pour vérification d'identité, sans débit.

      sudo bash deploy/vm/installer-vm.sh
      # → https://ecole.<ip-publique>.sslip.io  (HTTPS automatique)

  Options : --domaine ecole.mon-ecole.tg · --admin moi@exemple.tg
            --mot-de-passe '...' · --ip 1.2.3.4 · --verifier · --simulation

  Guide complet : LIEN-ETERNEL.md

===============================================================================
 QUI PEUT VOIR / MODIFIER QUOI (cloisonnement des professeurs)
===============================================================================

  Chaque professeur ne voit que les classes ET les matières que la direction
  lui a affectées (menu Enseignants → affectations). Côté serveur, la grille
  d'une autre matière répond 403, et l'écriture est refusée de la même façon.

    • un prof de Physique-Chimie n'ouvre PAS la grille de Mathématiques
      de la même classe, même en modifiant l'adresse ;
    • il ne voit pas les notes de son collègue (ni ne peut les modifier) ;
    • les bulletins d'une classe restent visibles aux profs de cette classe
      (un bulletin contient toutes les matières : c'est normal) ;
    • deux profs sur la MÊME matière peuvent co-saisir (remplacement) : la
      direction voit qui a modifié quoi dans le « Journal de saisie » de la
      page Saisie des notes ;
    • une période clôturée bloque toute saisie des professeurs ;
    • une note ne peut concerner qu'un élève de la classe de l'évaluation.

  Pour retirer un accès : Enseignants → 🚫 (bouton « Retirer l'accès »).
  Les sessions en cours sont fermées immédiatement et les affectations
  retirées ; ✅ « Rétablir » redonne l'accès. Les notes déjà saisies sont
  conservées dans tous les cas.
  Décocher une seule classe/matière (Enseignants → ✏️) reste possible pour
  un retrait partiel.

===============================================================================
 MOT DE PASSE OUBLIÉ D'UN ENSEIGNANT (c'est le chef qui le redonne)
===============================================================================

  La plateforme n'envoie pas d'e-mail (elle reste à 0 F). Le chef
  d'établissement est donc le seul à délivrer les identifiants.

  1) L'enseignant ouvre la page de connexion et clique
     « Mot de passe oublié ? », saisit son adresse et envoie.
  2) Le chef ouvre Enseignants : un bandeau jaune « 🔔 Demandes de mot de
     passe » apparaît en haut de page.
  3) Il clique sur 🔑 « Nouveaux identifiants » : un mot de passe lisible
     s'affiche (ex. baobab-solide-4821), avec un bouton 📋 Copier.
     ⚠ Il n'est affiché qu'UNE fois : notez-le ou dictez-le tout de suite.
     L'ancien mot de passe ne fonctionne plus et les sessions de
     l'enseignant sont fermées.
  4) Si le chef préfère imposer un mot de passe, il le tape dans le champ
     « Mot de passe imposé » avant de cliquer (6 caractères minimum).

  Le chef peut faire la même chose à tout moment, sans demande préalable :
  Enseignants → 🔑 (utile au téléphone : « votre nouveau mot de passe est… »).
  L'enseignant, lui, ne peut jamais se redonner un accès : le serveur refuse
  (403, action réservée à la direction).

===============================================================================
 MOT DE PASSE DE L'ADMINISTRATEUR (console éditeur)
===============================================================================

    npm run motdepasse                                   # nouveau mot de passe
    ADMIN_PASSWORD='MonSecret!2026' npm run motdepasse   # mot de passe imposé

  Le script met à jour la base, ferme les sessions ouvertes et réécrit
  data/compte-administrateur.txt. La base n'est pas modifiée autrement.

  Au démarrage, le lanceur VÉRIFIE réellement le mot de passe annoncé :
      « ✔ vérifié à l'instant »      → il fonctionne
      « ✘ non reconnu »              → un compte existe déjà : npm run motdepasse

===============================================================================
 BULLETINS : NOM ET SIGNATURE DU PROFESSEUR
===============================================================================

  Chaque professeur importe SA signature UNE SEULE FOIS :

      Console → Enseignants → ✏️ (modifier)
      → zone « Signature de l'enseignant »
      → glisser une photo de la signature (ou Ctrl+V / choisir un fichier)
      → Enregistrer

  Elle apparaît ensuite sur tous ses bulletins, au-dessus de son nom.

  Désigner le professeur principal d'une classe (celui qui signe) :

      Console → Classes → modifier → « Professeur principal »
      (il faut d'abord que l'enseignant existe et soit affecté à la classe)

  Signature du chef d'établissement :

      Console → Paramètres → Logo & signature → « Signature du chef
      d'établissement » → glisser la photo → Enregistrer ma signature

  Le bulletin affiche : nom du professeur sous chaque matière, puis deux
  blocs signés (Professeur principal / Chef d'Établissement).
  Le TUTEUR a été retiré du bulletin ; ses coordonnées restent dans la fiche
  de l'élève (usage administratif).

===============================================================================
 RANG ET BULLETINS DE COMPOSITION
===============================================================================

  Le RANG figure désormais partout :
    • sur chaque bulletin individuel : gros chiffre « 5/20 » dans le bloc
      « Résultats et positionnement », colonne « Rang » par matière,
      et dans l'appréciation (« il occupe la 5e place sur 20 élèves ») ;
    • sur la liste des bulletins de la classe (colonne Rang, triée) ;
    • sur le relevé des examens blancs (colonne Rang, 1er en tête) ;
    • dans les classements de la page Statistiques.

  BULLETINS DE COMPOSITION SEULE (option) :
    Console → Bulletins → « Type de bulletin » → Composition seule
    → 🖨️ Bulletins de composition (toute la classe) ou 🖨️ sur un élève.

    Le bulletin s'intitule « Bulletin de composition » : plus de colonnes
    Devoir 1 / Devoir 2, seules les compositions sont imprimées, et les
    moyennes générales comme les rangs sont recalculés sur la composition.
    Les bulletins complets restent disponibles : c'est une option
    d'affichage, rien n'est supprimé.

  STATISTIQUES DE COMPOSITION (page Statistiques, vue par classe) :
    • combien d'élèves ONT la moyenne en composition (≥ 10/20) ;
    • combien NE L'ONT PAS (< 10/20) ;
    • combien ne sont pas encore notés ;
    • la répartition « qui a 1, qui a 2, qui a 3… jusqu'à 20 » (graphique
      et tableau) ;
    • la composition par matière (nombre de notes, moyenne, ≥ 10, < 10).

 STOCKAGE EXTERNE : CLOUDINARY, DRIVE, MEGA (plusieurs comptes)

      CLOUDINARY_ACCOUNTS=cloud1|key1|secret1;cloud2|key2|secret2

      GOOGLE_DRIVE_SA_JSON=/chemin/cle.json
      GOOGLE_DRIVE_FOLDER_ID=1AbC...

      # MEGA (via rclone) :
      MEGA_RCLONE_REMOTE=mega:Terminish

  Diagnostic dans la console : GET /api/stockage/etat
  Détails : STOCKAGE-EXTERNE.md

 PUBLIER SUR FIREBASE
===============================================================================

  Firebase Hosting sert l'INTERFACE (gratuit, sans carte). Il ne peut pas
  exécuter le serveur Node + SQLite (plan Blaze = carte bancaire obligatoire,
  et disque éphémère = perte des notes).

  Combinaison qui marche à 0 F :
      interface  → Firebase Hosting
      API + base → votre machine (Tailscale Funnel)

  1. public/config.js :
         window.TERMINISH_API_BASE = 'https://penguin.xxxx.ts.net';
  2. sur le serveur :
         export CORS_ORIGIN="https://mon-ecole.web.app"
         export COOKIE_SECURE=1
         bash deploy/gratuit/tout.sh
  3. firebase deploy --only hosting

  Détails, limites et alternatives payantes : FIREBASE.md

===============================================================================
 « CETTE PAGE NE FONCTIONNE PAS » / HTTP ERROR 502 (lien .ts.net)
===============================================================================

  Le 502 ne vient pas de Tailscale : le nom et le certificat fonctionnent,
  mais le SITE n'est pas démarré sur le port 3000 (fenêtre fermée, veille,
  redémarrage du conteneur Linux).

      bash deploy/gratuit/tout.sh                    # REMET TOUT EN ROUTE
      bash deploy/gratuit/tout.sh --verifier         # diagnostic seul

  « ERR_NAME_NOT_RESOLVED » = le tunnel est FERMÉ (le nom .ts.net n'existe
  que tant que Funnel est ouvert) : même commande, tout.sh le rouvre.

      bash deploy/gratuit/service-auto.sh --etat     # état détaillé du service
      bash deploy/gratuit/service-auto.sh --installer # le site démarre tout seul

  --installer met le site en service avec relance automatique : plus besoin
  de garder « npm run partage » ouvert. Le lien .ts.net ne change pas.
  Autres commandes : --redemarrer · --arreter · --journaux · --simulation

 DÉPANNAGE EXPRESS
===============================================================================
  « Identifiants incorrects »   → en démo : admin1234 ; sinon npm run motdepasse
  Cannot find module 'node:sqlite'  → Node trop ancien (il faut 22+)
  502 Bad Gateway                   → docker compose logs app
  Session perdue en boucle          → cookie Secure sans HTTPS
  Données perdues au redéploiement  → aucun disque persistant monté sur /data
  Port 3000 déjà pris               → --port 3001
  Cloudflare Tunnel introuvable     → export PATH="$HOME/.local/bin:$PATH"
  Tailscale : command not found     → fermer/rouvrir le terminal, puis relancer
  « HTTPS is not enabled » (Funnel) → activer Enable HTTPS dans la console Tailscale
  « Funnel is not enabled »         → ouvrir le lien login.tailscale.com/f/funnel?node=…
                                      affiché, cliquer « Enable Funnel », relancer
  adresse en .ts.net peu parlante    → renommer la machine AVANT de distribuer le lien
                                      (admin/machines → Edit machine name)
  Le lien ts.net ne répond pas      → le site doit tourner : npm run partage
